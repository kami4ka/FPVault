# Оживлення

[English](BRINGUP.md) | Українська

## Стенд

- Плата в промпті U-Boot (U-Boot живе у SPI-NOR; бінарник DVR під час
  розробки вантажиться в RAM, тож цикл живлення завжди повертає в U-Boot).
- USB-serial на UART0 (PE0/PE1), 115200 8N1. Порт за замовчуванням у
  тулінгу: `/dev/cu.usbserial-0001` (перевизначення через `PORT=`).
- CVBS-камера на TV_IN як **високоомний паралельний відвід** від лінії
  камери. Не термінуйте: рівно один 75 Ом на лінію, і його місце — на боці
  VTX/дисплея (подвійна термінація вдвічі просаджує амплітуду, а AGC це
  ховає — виміряно важким шляхом у проєкті-попереднику).
- SD-карта в SDC0. FAT32.

## Розгортання

```sh
make            # build/fpvault.bin
make deploy     # YMODEM на 0x80000000 + go (tools/loader.py)
```

Команди консолі (один символ): `s` стан, `r` скидання watchdog'ом, `v`
інформація про VE, `q` перебір якості JPEG 50/75/90, `m` перебір вхідного
формату ISP, `J` кодування тест-патерну (лише таймінг), `j` кодування +
base64-дамп JPEG.

## Прошивання через USB — FEL (чиста або «зацеглена» плата, без UART)

FEL — режим відновлення в масковому ROM самого SoC: коли BROM не знаходить
завантажувального образу, він з'являється як USB-пристрій на тому самому
USB-C, що живить плату, і приймає завантаження. Тож щойно запаяна плата
прошивається одним лише USB-кабелем:

- **Чистий NOR** (свіжа плата): підключіть до комп'ютера — BROM сам
  провалюється у FEL.
- **Зайнятий або «зацеглений» NOR**: тримайте **SW2 під час підключення**.
  SW2 замикає пін NOR, тож SPI-проба BROM зазнає невдачі, і він потрапляє
  у FEL; відпустіть кнопку, щойно пристрій з'явився (~1 с). Сама
  флеш-пам'ять неушкоджена — коротке замикання лише «сліпить» пробу BROM.

На хості потрібні [sunxi-tools](https://github.com/linux-sunxi/sunxi-tools)
(`brew install sunxi-tools` / `apt install sunxi-tools`). Перевірка зв'язку:

```sh
sunxi-fel ver        # очікуйте: AWUSBFEX soc=00001663 (F1C100s/F1C200s)
```

Запис обох образів (U-Boot за адресою 0, прошивка з 1 МБ):

```sh
sunxi-fel -p spiflash-write 0        u-boot-sunxi-with-spl.bin
sunxi-fel -p spiflash-write 0x100000 build/fpvault.bin
```

Цикл живлення — і плата за ~5 с завантажується в запис. UART не потрібен
взагалі, хоча коли U-Boot уже в NOR, послідовний цикл `make deploy` вище —
швидший спосіб ітерувати прошивку.

Обидва бінарники прикріплені до GitHub Releases проєкту. Щоб зібрати
U-Boot самостійно (мейнлайн v2026.07 + два файли з `uboot/`):

```sh
git clone --depth 1 -b v2026.07 https://source.denx.de/u-boot/u-boot.git
cp uboot/f1c200s_dvr_defconfig          u-boot/configs/
cp uboot/suniv-f1c200s-video-board.dts  u-boot/dts/upstream/src/arm/allwinner/
make -C u-boot f1c200s_dvr_defconfig
make -C u-boot CROSS_COMPILE=arm-none-eabi- -j8
# результат: u-boot/u-boot-sunxi-with-spl.bin
```

Уся історія завантаження — в defconfig: `CONFIG_BOOTCOMMAND="sf probe;
sf read 0x80000000 0x100000 0x40000; go 0x80000000"`, автозапуск за 1 с.

## M1 — перше світло VE (go/no-go)

Єдине по-справжньому відкрите питання щодо кремнію: чи відповідає
JPEG-кодер Cedar VE на suniv так само, як на A10/A20 (jepoc)? Решта
продукту — перевірена земля.

1. `make deploy` — банер друкує `[ve] version XXXXXXXX`. Запишіть його.
   Самі нулі чи самі одиниці = проблема клоків/скидання; будь-що інше — це
   ID (старші 16 біт) і перше світло.
2. `python3 tools/vedump.py /dev/cu.usbserial-0001 --out ve.jpg`
   — надсилає `j`, ловить base64-дамп, декодує через PIL.
3. Прохід: JPEG відкривається і показує 8 кольорових смуг поверх градієнта
   яскравості, кольори правильні (переплутані U/V дають червонясті↔
   синюваті відтінки), 720×480, 20–150 КБ, час кодування друкується в мкс
   (очікуйте одиниці мс).
4. Переберіть `q` і зніміть дамп знову; розміри мають слідувати за якістю.
   Спробуйте `m`, щоб промацати питання значення формату NV16 (1 чи 2 —
   джерела розходяться).

Якщо статус не полишає 0 або читається "failed": перевірте `v` ще раз,
спробуйте альтернативні значення вибору суб-рушія (див. ve.h), потім менші
роздільності. Драбина відступу — в плані; рішення ухвалюється до того, як
вкладено будь-що інше.

## Усунення проблем

- **Мовчазна консоль**: плата без живлення, або U-Boot так і не стартував
  (SPI-NOR стертий?). Шлях відновлення — FEL через USB (sunxi-tools).
- **loader.py "no '=>' prompt"**: працює щось інше — натисніть reset; якщо
  живий попередній білд DVR/passthru, його команда `r` перезавантажує в
  U-Boot.
- **YMODEM висне з ESP32-мостом у лінії**: loader.py вже тримає DTR/RTS
  низькими, щоб не скидати міст; перевірте живлення самого моста.
