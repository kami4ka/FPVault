# Прошивка «голої» плати з Linux — інструкція для альфа-тестерів

Ця інструкція для тих, хто отримав плату FPVault **без прошивки**. Вона
описує, як залити прошивку з Linux через режим FEL, і що потрібно платі,
щоб працювати у двох різних режимах: підключеною до комп'ютера і без нього.

Є також окремі інструкції для [Windows](ALPHA-WINDOWS.uk.md) і
[macOS](ALPHA-MACOS.uk.md).

Актуальна версія прошивки на момент написання — **v0.9.6**.

Linux — найкоротший шлях із трьох: інструменти є у штатних репозиторіях,
драйверів ставити не треба (libusb працює з пристроєм напряму), а питання
підписів коду не виникає взагалі. Єдине, що є тут і чого немає деінде, —
правила доступу до USB-пристрою, і вони займають один файл.

---

## 1. Що знадобиться

**Залізо:**

- плата FPVault v1;
- кабель USB-C **з даними** (кабель «тільки для заряджання» не підійде);
- картка microSD (для запису; для самої прошивки не потрібна);
- аналогова камера CVBS і джерело живлення 5 В — знадобляться пізніше,
  коли перевірятимете запис.

**Файли** — з релізу проєкту
<https://github.com/kami4ka/FPVault/releases/latest>:

| файл | що це | куди пишеться |
|---|---|---|
| `u-boot-sunxi-with-spl.bin` | завантажувач | у NOR за адресою `0` |
| `fpvault.bin` | прошивка | у NOR за адресою `0x100000` (1 МБ) |

Потрібні **обидва**. Завантажувач містить виправлення, без якого плата
вмикається лише тоді, коли до неї приєднаний послідовний перехідник — тож
записати саму прошивку недостатньо.

---

## 2. Програмне забезпечення

`sunxi-tools` є у штатних репозиторіях усіх основних дистрибутивів.

**Debian / Ubuntu / Mint:**

```sh
sudo apt update
sudo apt install sunxi-tools dfu-util
```

**Fedora:**

```sh
sudo dnf install sunxi-tools dfu-util
```

**Arch / Manjaro:**

```sh
sudo pacman -S sunxi-tools dfu-util
```

Перевірка:

```sh
sunxi-fel --help
```

Має вивестись довідка зі списком команд, серед них `spiflash-write`.

> Якщо у вашому дистрибутиві пакета раптом немає, зберіть з вихідних
> кодів — потрібні `libusb-1.0` з заголовками, `pkg-config` і `make`:
> ```sh
> git clone --depth 1 https://github.com/linux-sunxi/sunxi-tools.git
> cd sunxi-tools && make tools && sudo make install-tools
> ```

## 3. Права доступу до USB

Без правил `udev` плата доступна лише root, і всі команди доведеться
запускати через `sudo`. Пакет `sunxi-tools` у Debian/Ubuntu уже
встановлює правило для FEL, але для режиму оновлення (DFU) у плати
власний ідентифікатор, якого не знає жоден готовий пакет.

Створіть файл `/etc/udev/rules.d/70-fpvault.rules`:

```sh
sudo tee /etc/udev/rules.d/70-fpvault.rules >/dev/null <<'EOF'
# Allwinner FEL - "гола" плата й відновлення
SUBSYSTEM=="usb", ATTR{idVendor}=="1f3a", ATTR{idProduct}=="efe8", TAG+="uaccess", MODE="0660", GROUP="plugdev"
# FPVault DFU - оновлення прошивки
SUBSYSTEM=="usb", ATTR{idVendor}=="34b7", ATTR{idProduct}=="f1c2", TAG+="uaccess", MODE="0660", GROUP="plugdev"
EOF

sudo udevadm control --reload-rules
sudo udevadm trigger
```

`TAG+="uaccess"` віддає пристрій тому, хто зараз працює за комп'ютером, —
цього достатньо на будь-якій сучасній системі з systemd. `GROUP="plugdev"`
залишено як запасний варіант для старіших систем; якщо такої групи у вас
немає, рядок однаково спрацює через `uaccess`.

**Перепідключіть плату після цього кроку** — правила застосовуються при
під'єднанні.

Якщо возитися з правилами не хочеться, можна просто додавати `sudo`
перед кожною командою нижче. Працює так само.

## 4. Переведення плати в режим FEL

FEL — це режим відновлення всередині самого процесора. Коли BROM не
знаходить, що завантажувати, він вмикає USB-режим і приймає дані. Саме це
робить «голу» плату прошиваною одним лише USB-кабелем.

- **Плата чиста (як ви її отримали):** просто під'єднайте USB-C до
  комп'ютера. BROM сам провалиться у FEL — нічого натискати не треба.
- **Якщо у NOR уже щось є** (наприклад, після невдалої спроби):
  натисніть і **тримайте SW2**, під'єднуючи кабель; відпустіть приблизно
  через секунду. SW2 замикає ніжку NOR, тож перевірка BROM зазнає
  невдачі й він потрапляє у FEL. Пам'яті це не шкодить — замикання лише
  «засліплює» перевірку.

`SW1` — це скидання, не плутайте.

Перевірити, що система бачить плату:

```sh
lsusb | grep 1f3a
```

Очікується рядок `ID 1f3a:efe8 Allwinner Technology`.

## 5. Прошивка

Перейдіть у теку із завантаженими файлами:

```sh
cd ~/Downloads
```

Спершу переконайтесь, що зв'язок є:

```sh
sunxi-fel ver
```

Очікуваний результат — рядок, що містить `AWUSBFEX` і `soc=00001663`.

Далі перевірте, що інструмент бачить флеш-пам'ять:

```sh
sunxi-fel spiflash-info
```

Має вивестись інформація про мікросхему. Це найкраща контрольна точка:
якщо флеш визначився, запис пройде.

Тепер два записи — **спочатку завантажувач, потім прошивка**:

```sh
sunxi-fel -p spiflash-write 0        u-boot-sunxi-with-spl.bin
sunxi-fel -p spiflash-write 0x100000 fpvault.bin
```

`-p` показує смужку прогресу. Завантажувач (≈415 КБ) пишеться близько
хвилини, прошивка (≈85 КБ) — швидше.

Коли обидві команди завершилися — **від'єднайте й під'єднайте кабель**.

---

## 6. Перевірка, що все вийшло

Під'єднайте плату USB-кабелем. Через кілька секунд:

```sh
lsusb | grep 34b7
```

Має з'явитися `ID 34b7:f1c2` — це вже прошита плата.

**Картка** змонтується автоматично у більшості робочих середовищ; якщо
ні — шукайте новий диск у `lsblk`.

**Камера** з'явиться як `/dev/video*`:

```sh
v4l2-ctl --list-devices          # з пакета v4l-utils
ffplay -f v4l2 -framerate 29.97 -video_size 720x480 /dev/video0
```

Або один кадр у файл:

```sh
ffmpeg -f v4l2 -framerate 29.97 -video_size 720x480 -i /dev/video0 -frames:v 1 shot.png
```

Якщо `shot.png` показує картинку з аналогової камери — плата жива й
прошита правильно. Зверніть увагу, що камера віддає **рівно** 720x480 і
29.97 кадр/с; інші значення застосунки відхилять.

## 7. Два режими роботи: з комп'ютером і без нього

Це найважливіше для розуміння поведінки плати, і воно часто дивує.

**Плата вирішує, ким їй бути, один раз — під час увімкнення.** Протягом
перших **2,5 секунди** після подачі живлення вона чекає, чи налаштує її
USB-хост. Далі шляхи розходяться і до наступного перезавантаження не
перетинаються.

### Режим «є хост» — плата під'єднана до комп'ютера

Комп'ютер визначив пристрій. Плата віддає картку комп'ютеру як
звичайний кардрідер і працює як вебкамера.

**Запису в цьому режимі немає.** Це не помилка: картка належить
комп'ютеру, і писати на неї одночасно з двох боків не можна.

### Режим «немає хоста» — автономний запис

Живлення є, а хоста немає — вікно очікування спливає через ті самі
2,5 секунди, і плата починає записувати сама.

«Немає хоста» означає буквально: ніхто не налаштував USB-пристрій.
Зарядний пристрій, павербанк або 5 В на майданчику `5V_IN` живлення
дають, але USB не піднімають — для плати це автономний режим.

Тож щоб перевірити **запис**, живіть плату від чого завгодно, крім
комп'ютера:

| живлення | режим |
|---|---|
| USB-C у комп'ютер | кардрідер + вебкамера, **без запису** |
| USB-C у зарядку чи павербанк | **автономний запис** |
| 5 В на майданчик `5V_IN` | **автономний запис** |

Живлення заходить або з USB-C, або з майданчика `5V_IN` через мультиплексор
TPS2116. Для прошивки користуйтеся **тільки USB-C**, зовнішнє живлення на
цей час від'єднайте — щоб не гадати, звідки плата живиться.

### Що означає світлодіод

Схема повторюється щосекунди:

| світлодіод | стан |
|---|---|
| горить постійно | **іде запис** |
| повільно блимає (пів секунди / пів секунди) | картка є, чекає на відеосигнал |
| подвійний короткий блим | **картки немає** або вона не змонтувалась |
| швидке рівне блимання | помилка |
| нерівномірне блимання | USB-режим (кардрідер) |

## 8. Що потрібно платі, щоб запис працював

Кілька пунктів, які виглядають як несправність, але є відомою поведінкою.
Повний перелік — у [HARDWARE-ERRATA.uk.md](HARDWARE-ERRATA.uk.md).

**Картку вставляйте до подачі живлення.** Пусковий струм картки при
«гарячій» вставці просаджує 3V3 нижче порога скидання, і плата
перезавантажується. Зараз це нешкідливо (плата просто перезавантажиться у
запис), але поводитись буде дивно.

**Картка має бути FAT32 з таблицею розділів MBR.** exFAT, яким з коробки
відформатовані всі картки понад 32 ГБ, прошивка не читає. Як підготувати
картку — розділ «Підготовка картки» у
[README.uk.md](../README.uk.md#підготовка-картки). Там же — про залишки
старого завантажувача на картці, які можуть перехопити завантаження
плати, і про те, як тримати картку чистою.

**Не тримайтеся за кут плати з мікросхемою живлення (EA3059), поки вона
під напругою.** Вузли зворотного зв'язку регулятора високоомні й
відкриті; ємності пальця вистачає, щоб збити напругу і перезавантажити
плату.

**Живлення від павербанка може давати спонтанні перезавантаження.**
Виміряно: ~35 хвилин від павербанка — 5 перезавантажень, від зарядки —
2, від USB-порту комп'ютера — жодного. Причина — просадка живлення на
картці під час запису. Лікується конденсатором ≥100 мкФ біля роз'єму
SD (220 мкФ на стенді прибрали всі три відомі симптоми). Якщо на вашому
екземплярі цього конденсатора немає, для тривалих тестів беріть
живлення якісніше.

**Якщо картка «залипла», перезавантаження не допоможе.** Скидання
процесора не знімає живлення з картки. Допомагає лише фізично вийняти
картку з роз'єму — саме вийняти, бо якщо конденсатор встановлено, він
утримує живлення картки ще хвилини після від'єднання кабелю.

## 9. Подальші оновлення — без FEL

Коли прошивка вже на платі, FEL більше не потрібен: плата оновлюється
через DFU по тому ж кабелю, і SW2 натискати не треба.

```sh
dfu-util -d 34b7:f1c2 -a 0 -D fpvault.bin
```

(якщо не робили правила `udev` з розділу 3 — додайте `sudo`)

Плата сама перевіряє образ, записує його, зчитує назад для звірки і лише
тоді перезавантажується. До завершення передачі у флеш нічого не
пишеться, тож висмикнутий на півдорозі кабель нічого не псує.

Оновлювати завантажувач через DFU **не можна** — DFU пише лише прошивку.
Якщо в описі релізу буде позначка, що потрібне відновлення, це означає
повернення до FEL і розділу 5.

## 10. Якщо щось не так

**`sunxi-fel ver` пише `ERROR: Allwinner USB FEL device not found!`, хоча
`lsusb` пристрій показує.** Це майже завжди права доступу: або зробіть
правила `udev` з розділу 3 і перепідключіть плату, або запускайте через
`sudo`.

**`lsusb` не показує нічого.** Кабель без даних — найчастіша причина;
спробуйте інший. Якщо не допомогло — тримайте SW2 під час під'єднання
(розділ 4).

**`sunxi-fel spiflash-info` не бачить флеш.** Перепідключіть плату з
затиснутим SW2 і повторіть. Якщо `ver` працює, а `spiflash-info` — ні,
плата майже напевно вийшла з FEL.

**Плата не вмикається без послідовного перехідника.** Записаний старий
або непропатчений завантажувач. Перезапишіть `u-boot-sunxi-with-spl.bin`
саме з релізу.

**`/dev/video0` є, але це вбудована вебкамера.** Номери залежать від
порядку під'єднання. `v4l2-ctl --list-devices` покаже, який саме вузол
належить `FPVault Camera`.

**Плата не записує, хоча картка вставлена.** Швидше за все вона
під'єднана до комп'ютера й перебуває у режимі кардрідера — це очікувано
(розділ 7). Живіть її від зарядки або від `5V_IN`.

## Коротко

Один раз:

```sh
sudo apt install sunxi-tools dfu-util      # або dnf / pacman

sudo tee /etc/udev/rules.d/70-fpvault.rules >/dev/null <<'EOF'
SUBSYSTEM=="usb", ATTR{idVendor}=="1f3a", ATTR{idProduct}=="efe8", TAG+="uaccess", MODE="0660", GROUP="plugdev"
SUBSYSTEM=="usb", ATTR{idVendor}=="34b7", ATTR{idProduct}=="f1c2", TAG+="uaccess", MODE="0660", GROUP="plugdev"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
```

Далі, з платою в режимі FEL:

```sh
cd ~/Downloads
sunxi-fel ver
sunxi-fel spiflash-info
sunxi-fel -p spiflash-write 0        u-boot-sunxi-with-spl.bin
sunxi-fel -p spiflash-write 0x100000 fpvault.bin
```

Перезавантажити живлення — і плата готова.
