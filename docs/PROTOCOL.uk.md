# Інтерфейси керування

[English](PROTOCOL.md) | Українська

## RunCam Device Protocol v1.0 (бік пристрою)

Єдиний протокол керування записом, яким володіють одразу Betaflight, INAV
і ArduPilot. UART1 (PA2 TX / PA3 RX), 115200 8N1, без інверсії, 3,3 В.

Кадри FC → пристрій (`[0xCC][cmd][params][crc8]`, без байта довжини; CRC8
DVB-S2, поліном 0xD5, по всіх байтах включно із заголовком):

| Кадр | Значення | Наша відповідь |
|---|---|---|
| `CC 00 crc` | GET_DEVICE_INFO | `CC 01 C5 00 crc` (прото 1, можливості 0x00C5) |
| `CC 01 01 E7` | кнопка живлення | перемкнути запис, **без відповіді** |
| `CC 01 03 98` | почати запис | старт (ідемпотентно), без відповіді |
| `CC 01 04 CC` | зупинити запис | стоп (ідемпотентно), без відповіді |
| `CC 01 00/02 …` | кнопка wifi / зміна режиму | розібрано, ігнорується |
| `CC 02/03/04 …` | емуляція 5-кнопкового OSD | розібрано, ігнорується (можливість не заявлена) |

Можливості 0x00C5 = SIMULATE_POWER_BUTTON | CHANGE_MODE | START_RECORDING |
STOP_RECORDING. Біти 6/7 змушують ArduPilot користуватись явними
старт/стоп; Betaflight та INAV завжди шлють лише перемикання кнопкою
живлення. Відповідь на CAMERA_CONTROL розсинхронізувала б парсер
Betaflight — пристрій мовчить навмисно. FC зондує ~7 с після завантаження
(типово для ArduPilot); повторювані GET_DEVICE_INFO — норма.

Налаштування FC:
- **Betaflight/INAV**: Ports → Peripherals → "RunCam Device" на
  під'єднаному UART; Modes → `CAMERA POWER` на AUX-перемикач (поставте на
  діапазон ARM для запису при армуванні).
- **ArduPilot**: `SERIALx_PROTOCOL=26`, `CAM1_TYPE=8`, `CAM1_RC_TYPE=2`,
  `RCx_OPTION=78` (старт/стоп запису).

## GPIO-пін запису (запасний варіант без FC)

Один вхідний пін, три придатні стилі сигналу (заплановано, M6):
- рівень: високий = запис, низький = стоп;
- імпульс > 100 мс = перемикання (відповідає режиму pulse у Betaflight
  PINIO);
- RC PWM 1000–2000 мкс: > ~1700 мкс = запис, з гістерезисом ~60 мс.

## Поведінка за замовчуванням

Автозапис за валідним відео: запис стартує після ~1 с стабільного V_LOCK і
зупиняється при тривалій (≥5 с) втраті сигналу або явній команді стоп;
короткі провали залишаються всередині кліпу як порожні кадри, що
зберігають таймінг.

## Світлодіод (PE3)

світиться постійно = запис · повільне блимання = озброєний, чекає
сигналу/команди · подвійне блимання = немає карти/карта заповнена · швидке
блимання = помилка.
